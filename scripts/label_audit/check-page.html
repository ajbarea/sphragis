Label audit: blind check of rater A

384 examples from the Stage 1 training and dev windows, in a fixed random order. Label each one blind, then reveal what rater A chose. Your blind label is locked when you reveal, and it is the one agreement is computed from, so any stopping point gives a fair sample. The organization is not shown, though a file path can give it away; judge only what the comment asked and what the rewrite did.

How to label: two questions per example

1. The label. Did the reviewer ask for a change, and is the rewrite the author's answer to it?

valid
The comment asks for a change and the rewrite makes it. Extra edits alongside are fine.
non_actionable
The comment asks for no change (praise, FYI, agreement, a question answerable in words), or withdraws the request.
unrelated_rewrite
The requested change is absent; the code changed for some other reason.
partial
The rewrite makes part of what was asked, or makes it clearly differently than suggested.
context_dependent
You cannot tell what the comment asks for from what is shown: "same here", "see above", other lines or patch sets, a bare "?", "remove" without saying what, only a link.

context_dependent is about understanding the request. A clear request answered with names defined elsewhere is still valid; that is question 2. Several comments: all actionable requests made is valid, some is partial, none is unrelated_rewrite.

2. Names from outside. Does the rewrite use a name or value that appears nowhere in the example (a helper, constant, module, config key, version or hash)? Names the comment spells out count as shown; new local names and ordinary library names do not count.

Keys: 1–5 label, x names from outside, Enter reveal, n / p next and previous. Example 1 is a worked example and is not counted.
